# Архитектура

`cmd/client`, `cmd/server` — точки входа. `internal/cli` — команды; `internal/client` — HTTPS, кэш и синхронизация; `internal/vault` — криптография; `internal/model` — wire contract и секреты. `internal/api` проверяет запросы и сессии; `internal/store` использует pgxpool. `internal/serverapp` управляет TLS и graceful shutdown. `internal/testutil` содержит тестовые fixtures и не импортируется приложениями.

## Хранение

User: bcrypt-хэш входа, случайная соль и encrypted key check. Session: SHA-256 случайного 256-битного токена, владелец, срок (24 часа). Record: ключ `(login,id)`, revision, deleted, data. В data зашифрованы тип, title, metadata и всё содержимое.

`internal/store/schema.sql` встроена в бинарник; установка схемы транзакционна под advisory lock. Следующие изменения потребуют последовательных версионированных миграций: CREATE TABLE IF NOT EXISTS не обновляет существующие таблицы.

## Протокол синхронизации

1. Клиент шифрует изменение новым nonce и сохраняет его с исходной ревизией и случайным operation ID.
2. Очередь отправляется в порядке ID записей.
3. Сервер блокирует строку пользователя, проверяет журнал операций, ревизию и квоты; запись и подтверждение фиксируются атомарно.
4. Повтор того же запроса возвращает исходную ревизию. Другой запрос с тем же operation ID получает 409.
5. Клиент получает полный снимок своего namespace с tombstones и заменяет кэш после проверки ответа.

Потеря ответа или завершение процесса до сохранения кэша не создаёт дубликат: сохранённая очередь содержит прежний operation ID. Ошибка останавливает текущий push, не откатывая уже отправленные записи.

Tombstone неизменяем. Сохранение локальной версии поверх удаления создаёт новый ID и новое шифрование с соответствующим AAD. После разрешения конфликта возможна новая гонка; она снова обнаруживается по версии.

Квота снимка — 64 МиБ ciphertext; base64 увеличивает HTTP-ответ. Файлы до 8 МиБ обрабатываются целиком. Журнал операций содержит компактные подтверждения без второй копии ciphertext. История и tombstones не очищаются автоматически: очистка потребует протокола согласования со всеми клиентами. Администратор отвечает за место и backups.
