# Безопасность

HTTPS проверяет сертификат, TLS >=1.2. Собственный CA задаётся через --ca. Redirect запрещён. HTTP возможен только с явным --dev-http на loopback.

Содержимое и metadata шифруются AES-256-GCM на клиенте. Каждый ciphertext имеет новый случайный 12-байтный nonce; AAD привязывает запись к логину и ID. Формат: версия 1, nonce, ciphertext, 16-байтный tag. Ключ Argon2id: 3 прохода, 64 МиБ, 4 lanes, 32 байта; случайная соль 16 байт на аккаунт. Параметры фиксированы для v1. Пароль хранилища никогда не отправляется серверу и отличается от пароля входа.

Пароль входа: bcrypt DefaultCost, 12–72 байта. Лимитер по логину и ограничение параллельных bcrypt-проверок. Dummy hash уменьшает разницу времени при отсутствующем пользователе. Сессия — случайный 256-битный токен; на сервере только SHA-256, срок 24 часа, logout отзывает токен.

Владелец SQL-операций берётся из сессии, не из тела запроса. Транзакционная блокировка аккаунта защищает сравнение ревизий и квоты. Повреждение ciphertext, неверный ключ или AAD отклоняются.

## Границы

Сервер видит логины, соль, ID, размеры, ревизии и удаления. Он получает пароль входа при аутентификации — поэтому использовать его же для шифрования нельзя. Дамп позволяет офлайн-подбор пароля хранилища: нужен длинный уникальный пароль. Защиты от злонамеренного удаления или отката всей базы нет.

Нет защиты от вредоносного ПО на разблокированном клиенте, чтения памяти и скомпрометированной ОС. Go не гарантирует удаления всех копий строк из памяти. Очистка рабочего ключа best effort. Явный get выводит plaintext.

Ошибки разбора JSON секретов не включают пользовательские имена полей или значения. Выход удаляет локальный токен как после успешного отзыва, так и после ответа 401 об уже недействительной сессии; сетевые ошибки и ошибки сервера сохраняют токен для повторного отзыва. Зашифрованные записи и очередь при выходе сохраняются.

Кэш содержит ciphertext и открытый токен сессии. Unix-права 0600/0700 ограничивают доступ; Windows использует ACL профиля. Не передавайте кэш недоверенным пользователям. Файлы --input, паролей и экспорта содержат plaintext; не коммитьте их.

Для публичного сервиса нужны управление TLS/DB-секретами, backups, дисковые квоты, мониторинг и общие ограничения трафика/регистраций на reverse proxy. Встроенный лимитер не распределённый. Журнал идемпотентности хранится бессрочно; планируйте дисковое место.

При повторном входе клиент сверяет неизменность логина, соли и контрольного шифротекста до сохранения сессии и отправки очереди. Это предотвращает смешивание данных разных ключей после пересоздания аккаунта.

Смена/восстановление паролей, ротация ключей, MFA и разделение устройств отсутствуют. Потерянный пароль хранилища восстановить нельзя. Это учебный проект без независимого аудита. Алгоритмы берутся из Go stdlib и golang.org/x/crypto.
